# 模块 B：事实缺口识别（补充材料清单与会见提纲）

## 一、适用时机与输入

- **触发**：用户要求"识别事实缺口""还有哪些事实需要核实""帮我列补充材料清单""准备首次会见提纲"等。
- **输入**：模块 A 的案情梳理成果（主体、分层法律关系、时间线、核心矛盾）。若对话中尚无模块 A 成果，先复用用户已提供的案情；信息不足时一次性追问，不挤牙膏。
- **面向对象**：本模块直接服务于**客户沟通**——产出可用于《补充材料清单》和首次会见询问提纲。

## 二、方法论：从"要件"反推"事实缺口"

事实缺口 = 对判断本案法律问题有重大影响、但案情中**没有说明或说明不清**的事实。

识别路径（由法律要件反推事实，而非泛泛地问"还有什么没告诉我"）：

1. **锁定法律问题**：依据模块 A 的核心法律关系与核心矛盾，列出支撑判断所需的法律问题。
2. **拆解构成要件**：对每个法律问题，列出其成立所需的构成要件事实、抗辩要件事实、程序要件事实。
3. **比对现有案情**：逐一核对这些要件事实，标记"已明确 / 未说明 / 说明不清 / 相互矛盾"。凡属"未说明/说明不清/相互矛盾"且影响结论的，即为事实缺口。
4. **排除无关项**：与本案法律问题无关的事实缺口不列入，避免清单冗长失焦。

## 三、每项缺口的三问分析

对每一项待核实事实，必须回答三问：

1. **为什么重要**：它会影响哪个法律问题的判断？（对应到具体法律问题，不泛泛而谈）
2. **两种情形下的结论方向**：若该事实**存在**，结论可能向哪个方向变化；若**不存在**，又向哪个方向变化。这是本模块的核心价值——让客户明白"为什么这份材料非补不可"。
3. **核实途径**：通常可通过什么证据材料核实？如协议文本、补充协议、工商登记档案、公司章程、股东会/董事会决议、出资凭证、银行流水、验资报告、股权转让协议、完税凭证、往来函件、微信/邮件记录、会议纪要、审计报告、评估报告、证人证言等。

## 四、重要性分级标准

按对案件走向的影响程度，分三级并**按重要程度排序**：

| 等级 | 判定标准 |
|------|----------|
| **关键** | 该事实的有无直接决定核心法律关系或核心争议的成立与否，缺失则无法下任何结论 |
| **重要** | 该事实显著影响责任范围、抗辩成立、请求权选择或金额认定 |
| **一般** | 该事实影响细节认定或补强论证，不改变案件基本走向 |

## 五、输出模板

### 主产出：事实缺口表

严格用表格，列为：**待核实事实｜重要性等级｜影响的法律问题｜不同情形下的结论方向｜核实途径**。按重要性从高到低排序。

```
基于上述案情与法律关系梳理，本案存在以下事实缺口（按重要程度排序）：

| 序号 | 待核实事实 | 重要性等级 | 影响的法律问题 | 不同情形下的结论方向 | 核实途径 |
|------|-----------|-----------|----------------|----------------------|----------|
| 1 | | 关键/重要/一般 | | 若存在：……；若不存在：…… | |
| 2 | | | | | |
```

### 附加产出一：《补充材料清单》（可选，用户需要时生成）

将上表"核实途径"列按证据类型归并，形成可直接发给客户的材料清单：

```
《补充材料清单》
一、协议类文件
1. ……（对应待核实事实 1，用于证明……）
二、公司登记与决议类文件
1. ……
三、资金往来凭证
1. ……
四、往来沟通记录
1. ……
（每项标注用途与对应的事实缺口编号，关键项注明"务必提供"）
```

### 附加产出二：首次会见询问提纲（可选，用户需要时生成）

将"关键""重要"级缺口转化为可直接询问客户的问题，按主题分组：

```
首次会见询问提纲
一、关于【核心法律关系/合同签订】
1. 请问……？（对应事实缺口 1，目的在于确认……）
二、关于【款项/履行情况】
1. ……
三、关于【股权变动/登记】
1. ……
（每个问题注明对应的待核实事实编号与询问目的；关键问题前置）
```

## 六、质量自检

- [ ] 每项缺口是否都能对应到具体法律问题，而非泛泛的"信息不全"？
- [ ] 每项是否都写明了"存在/不存在"两种情形下的结论方向？
- [ ] 核实途径是否具体到了可操作的证据材料？
- [ ] 重要性分级是否有依据、排序是否合理？
- [ ] 是否排除了与本案无关的缺口？
- [ ] 事实与法律是否分离（本模块只问事实，不在此处下法律结论）？
