# 模块 D：法律问题清单与检索方向

## 一、适用时机与输入

- **触发**：用户要求"形成法律问题清单""本案需要研究哪些法律问题""给我检索方向/检索关键词"等。
- **输入**：模块 A 的案情梳理成果，及（如有）模块 C 的争议焦点。复用对话中已有成果；不足时一次性追问。

## 二、方法论

### （一）形成法律问题列表

1. **表述要求**：每个问题必须是能用"**是/否**"或"**如何认定**"回答的具体法律问题，不得写成"本案如何处理"这类笼统设问。
   - 合格："股权受让人是否当然承继原股东的回购义务？"
   - 不合格："本案回购问题怎么处理？"
2. **区分前提性与结果性**：标注每个问题属于"前提性问题"还是"结果性问题"，并说明问题之间的逻辑先后关系（如"必须先解决问题 A，才有讨论问题 B 的必要"）。
3. **标注法律领域**：为每个问题标注所属法律领域（合同法、公司法、担保制度、民事诉讼法、民法总则等）。

### （二）给出检索方向建议

针对每个法律问题，提供三项：

1. **规范大致范围**：可能涉及的法律、司法解释、会议纪要、指导性案例的范围（如"《民法典》合同编、《九民纪要》关于对赌的规定、最高人民法院关于股权转让的相关指导案例"）。
2. **检索关键词组合**：给出 **3–5 组**关键词，**必须包含同义表达和实务中法院常用的表述**。这是提高案例命中率的关键。
3. **裁判分歧提示**：该问题在实务中是否存在明显争议或裁判分歧；如有，简要说明分歧在哪里。不确定时直接说"我不确定，需检索验证"。

### （三）确定优先级

若检索时间有限，建议**优先检索哪 2 个问题**，并说明理由（通常选择：前提性 + 决定案件走向 + 存在裁判分歧的问题）。

## 三、检索关键词策略（核心技巧）

法院判决书的表述往往与教科书不同。提供关键词时遵循：

1. **以法院实务表述为主，而非学理概念**。例如研究回购问题，法院更常用"股权回购义务""回购义务人""股权转让后的合同义务承担"，而非抽象的"合同义务移转"。
2. **每个问题给出多组同义/近义表达**，覆盖：
   - 规范用语（法条原文用词）
   - 实务用语（判决书高频表述）
   - 通俗表达（当事人陈述常用语）
3. **组合维度**：主体词 + 行为词 + 争议词。如"目标公司 + 回购 + 效力""创始股东 + 股权转让 + 义务承继"。
4. **配合使用检索工具**：语义检索（自然语言案情）与关键词检索交叉，0 结果时换同义词重试至少 2 轮。具体工具参数见 `legal-search-guide.md`。

## 四、输出模板

法律问题用**编号列表**，检索方向用**表格**：

```
一、法律问题列表
1. 【问题表述，可用是/否或如何认定回答】
   - 类型：前提性问题 / 结果性问题
   - 法律领域：……
   - 逻辑关系：……（如"系问题 2 的前提，须先行解决"）
2. ……（同上）
（最后可用一句话概括问题之间的整体先后关系）

二、检索方向建议
| 序号 | 法律问题 | 规范大致范围 | 检索关键词组合（3-5 组，含同义表达与实务表述） | 实务争议/裁判分歧 |
|------|----------|--------------|----------------------------------------------|-------------------|
| 1 | | | ①…；②…；③…；④… | |

三、优先级
建议优先检索：问题 X、问题 Y。
理由：……（前提性 / 决定案件走向 / 存在裁判分歧）
```

## 五、质量自检

- [ ] 每个问题是否都能用"是/否"或"如何认定"回答？
- [ ] 是否区分了前提性与结果性问题，并说明了逻辑先后？
- [ ] 每个问题是否标注了法律领域？
- [ ] 每个问题是否给出了 3–5 组关键词，且包含实务表述与同义表达？
- [ ] 裁判分歧处，不确定的是否如实标注"我不确定，需检索验证"，未编造？
- [ ] 优先级是否给出明确的 2 个问题及理由？
