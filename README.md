# workbuddy-legal-case-analyzer

> 执业律师视角的案件分析 Skill：案情梳理与法律关系分层 → 事实缺口识别 → 争议焦点拆解 → 法律问题清单与检索方向。

仓库名为 `workbuddy-legal-case-analyzer`；技能在 WorkBuddy 中的目录名与技能名（`SKILL.md` 的 `name`）为 `legal-case-analyzer`。

一个适用于 [WorkBuddy](https://www.workbuddy.cn) 的 Skill。以执业十年以上中国律师的工作方法，把一段无序的案情描述，转化为可据以判断、举证与检索的结构化分析底稿。支持结合北大法宝、元典等法律数据库检索真实法条与类案。

## 四个模块

四个模块可**独立调用**，也可按 **A → B → C → D** 顺序串联。

| 模块 | 功能 | 关键产出 |
|------|------|----------|
| **A　案情梳理与法律关系分层** | 主体梳理 → 分层识别法律关系（双方主体/法律性质/产生依据 + 核心层）→ 关键时间线 → 核心矛盾概括 | 分节标题 + 编号列表；时间线表格；不急于下结论 |
| **B　事实缺口识别** | 从构成要件反推事实缺口，逐项回答"为何重要 / 存在与否的结论方向 / 核实途径"，按关键·重要·一般分级 | 事实缺口表；《补充材料清单》；首次会见询问提纲 |
| **C　争议焦点分层拆解** | 事实 / 法律适用 / 程序三层拆解；法律适用焦点细化为可独立检索子问题；焦点逻辑链 | 三级编号（一、1、（1））+ 末尾逻辑链条文字 |
| **D　法律问题清单与检索方向** | "是/否"或"如何认定"的具体提问；前提性/结果性区分；法律领域标注；3–5 组检索关键词（含法院实务表述同义词）；裁判分歧；优先级 | 法律问题编号列表 + 检索方向表格 |

## 全局铁律

Skill 内置以下约束，每次输出都必须遵守：

1. **事实问题与法律问题严格分离**。
2. **法条引用**：写明法律名称 + 条文序号 + 是否现行有效 + 生效日期；不确定标"需核实"，不编造。
3. **案例引用**：写明案号 + 审理法院 + 裁判日期；无法确认标"待核实"，不虚构案号。
4. **不确定声明**：不确定处直接说"我不确定"并说明原因。
5. **语言与格式**：专业、简洁的法律语言，优先结构化输出（标题、编号、表格）。

## 安装

将本目录整个复制到 WorkBuddy 的用户级 skills 目录：

- **Windows**：`C:\Users\<你的用户名>\.workbuddy\skills\legal-case-analyzer`
- **用户级**：对该账号所有项目生效。

放置后，在 WorkBuddy 对话中即可通过触发词调用。

## 使用

直接在对话中粘贴案情并提出需求即可，例如：

- 「帮我梳理这个案子的主体和法律关系」（触发模块 A）
- 「这个案子还有哪些事实需要核实？帮我列个补充材料清单」（触发模块 B）
- 「帮我拆解本案的争议焦点」（触发模块 C）
- 「帮我形成法律问题清单和检索关键词」（触发模块 D）

模块间可串联：完成模块 A 后，可继续要求做 B / C / D。

## 依赖

- **WorkBuddy**：本 Skill 的运行环境。
- **法律数据库 Connector**（用于真实检索，可选但推荐）：北大法宝（pkulaw）、元典（yuandian-mcp）。未授权的数据库会自动跳过，不阻塞分析流程；但此时引用的法条与类案需人工核验。

## 与其它 Skill 的关系

本 Skill 产出的是**分析过程与工作底稿**（清单、表格、提纲、检索方案），而非成文法律意见书。若需正式研究报告，可在其基础上转交 `legal-research-report` Skill；若需生成 Word 文件，转交 Office 相关 Skill。

## 免责声明

本 Skill 输出的法条、案号、裁判要旨等内容，即使是经检索获得，也**必须在使用前打开来源链接核对原文与现行有效性**。AI 分析不构成法律意见，不能替代执业律师的独立判断。
